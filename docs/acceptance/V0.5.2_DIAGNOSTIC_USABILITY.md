# v0.5.2：诊断、可读性与受控重试验收

## 真实失败与第一性原理

执行日期：2026-08-27。

目标用户仍是本机单个面试准备者。最短完整路径没有变化：双击启动、打开 loopback 聊天页、提交问题、理解回答或失败、核对本轮引用、按需恢复或删除历史、最后双击停止。用户不应理解 FastAPI、供应方 `finish_reason`、HTTP 错误或 SQLite 才能完成这条路径。

本轮由连续真实使用暴露四类问题：

1. 连接失败只显示英文 `The answer model could not complete the request.`，消息区和输入框上方还会重复显示；用户无法区分本机服务、网络、endpoint 或远端模型问题。
2. 旧验收配置 `LLM_MAX_TOKENS=256` 在日常口述回答中得到 HTTP 200，却以 `finish_reason=length` 停止。Agent 正确拒绝截断正文，但启动检查没有在提问前阻止这项已知失败配置。用户手动改为 1200 并在本机重启后成功完成回答。
3. 成功回答中的 `**粗体**`、编号和行内代码按原始 Markdown 显示，信息可读性不足。
4. 一次公开技术问题得到 `medium` 证据强度，唯一引用实际是无关主题的 notes 文档，分数约 `0.5850`，只略高于冻结的 notes 阈值 `0.58`；旧界面没有显示该强度，用户容易把“有引用”误认成“引用支持回答”。

需要持久化的仍只有受控会话字段。错误正文可以保存稳定代码与固定公开说明，但不得保存供应方异常、绝对路径或密钥片段。失败边界是：不展示截断回答、不自动重试可能已经产生费用的调用、不把失败轮旧引用带入新一轮、不把格式渲染升级为任意 HTML。

可验证验收标准是：已知 256 输出上限在启动前失败；1200 通过；成功回答有限格式可读；HTML/链接不可执行；每个失败只显示一处中文主说明；可重试项必须经费用确认且只提交一次；HTTP 与历史不含恶意错误正文；中低证据始终明确提示核对引用；Phase 2 全回归不退化。

## 实现范围

- preflight 增加 `llm_output_budget`：不大于 256 直接失败，257–1199 提醒，1200 及以上通过。1200 是上限而非固定消耗量，不改变模型提示或调用次数。
- preflight 增加 `runtime_profile`：`DATABASE_PATH` 或 `VECTOR_STORE_PATH` 含 `acceptance` / `acceptance-*` 分段时提醒日常状态混用；程序不自动移动或删除旧 SQLite、Chroma 或历史。
- 回答增加不依赖第三方库的有限格式解析，只支持段落、粗体、编号/无序列表和行内代码。格式 token 通过安全 DOM API 渲染；结构化 citation 芯片仍只来自 API 的 `citations`。
- 成功回答始终显示证据匹配强度；`medium` 明确要求核对引用，`low` 标记仅作参考，并说明该指标不是模型正确率。
- 失败消息改为中文固定映射，只在对应消息内显示一次；折叠诊断仅含稳定错误码和追踪标识。
- 固定可重试错误增加“手动重试”。点击后必须确认重新检索、一次远端调用和潜在费用；重试沿用当前 session，但不会把相同失败问题作为 `previous_question`。
- HTTP 与 SQLite 历史在边界处再次净化 Agent 错误。错误码只允许小写字母、数字和下划线，任意错误正文替换成固定公开消息。

本版本没有修改会话 schema、Phase 2 检索阈值、Top-K、候选排序、Router、RAG、提示词、答案接受条件或引用校验，也没有读取或改写真实 Vault 正文。

## 对抗性测试与结果

| 场景 | 预期边界 | 结果 |
|---|---|---:|
| `<img onerror>`、`<script>`、`javascript:` Markdown 链接 | 保持纯文本，不建立 HTML 或链接 | 通过 |
| 未闭合粗体/代码标记 | 不吞字、不制造元素 | 通过 |
| 回答正文伪造 `[S999]` 或 `file:///` | 仅正文文本；不能生成 citation 芯片 | 通过 |
| 恶意/非字符串错误码、伪真重试值、绝对路径和密钥片段 | HTTP 与历史只含安全类型、错误码和固定文案 | 通过 |
| 可重试失败 | 无定时器、唯一 `/ask` 入口、确认后一次提交 | 通过 |
| 相同问题手动重试 | 沿用 session，但不作为上一问上下文 | 通过 |
| `LLM_MAX_TOKENS=256` | preflight 失败并给出 1200 修复动作 | 通过 |
| 日常运行时仍指向 `acceptance-*` | 明确提醒，不迁移或删除数据 | 通过 |
| 中/低证据成功回答 | 显示“核对引用”或“仅作参考” | 通过 |
| 发送中的 `pending` 临时轮次 | 正常等待样式，不误显示为失败诊断 | 通过 |

定向 Python 测试为 **27 passed**。默认离线全回归为 **338 passed、4 skipped**；四个 skip 仍是显式真实本地 Embedding 或远端 LLM 入口。Node 语法检查和独立安全格式对抗脚本通过。当前本机配置的只读 preflight 扫描 120 个 Markdown 文档，输出上限通过、0 项失败、1 项运行时配置提醒。本机现有服务的 `/health` 与首页、主脚本、安全格式脚本均返回 HTTP 200；另在 8001 临时冷启动 v0.5.2 包，确认 `health=ok`、首页 200 后关闭。上述过程只读取静态资源，没有请求 `/ask`。

v0.5.2 自动化过程没有提交问题，没有加载或下载 Embedding，没有建立新索引，也没有发起新的真实远端 LLM 调用。用户在本轮开发前自行完成的一次成功调用仅用于证明把本机输出上限从 256 改为 1200 后截断问题消失；它不作为自动化回归授权。

## 指标变化、失败归因和剩余风险

- Phase 2 固定检索指标没有重跑或重算，冻结配置和四个显式 skip 原样保留；本轮新增通过项只证明产品交互和安全边界。
- 无关 notes 引用是已确认的语义假阳性：向量分数约 `0.5850` 刚越过 `0.58`，回答又使用了引用之外的通用知识。显示 `medium` 和核对提醒降低误用风险，但不修复检索或语义蕴含本身。
- 不能在 v0.5.x 通过提高/降低阈值、扩大答案、删除样本或改提示词制造绿灯。若要真正修复该假阳性，需要用户另行决定是否重开检索/回答语义正确性阶段，并先增加冻结的同类负例与独立留出验证。
- 当前 `.env` 的 SQLite 和向量路径仍沿用旧验收目录。直接切换到产品默认路径会让界面看不到旧会话，并可能触发独立索引初始化；因此本版本只提醒，不静默迁移。是否切换、是否保留或删除旧运行时数据由用户决定。
- 有限格式刻意不支持标题、表格、代码块或 Markdown 链接；这是缩小注入面和保持引用芯片权威性的产品边界，不是完整 Markdown 渲染器。
