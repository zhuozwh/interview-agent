# v0.5.0：本地产品化与可用性闭环

## 发布定位

执行日期：2026-08-27。

v0.5.0 从 `main`、本地 `origin/main` 和 annotated `v0.4.6` peeled commit 共同指向的 `b929cff94697c1cfcbe758fea3a2e8997af5dc67` 开始。v0.4.6 及以前未修改；Phase 3 版本线直接从 v0.5.0 开始，不使用 v0.4.7 或 v5 命名。

本版本只解决本地单用户的产品入口、历史生命周期和启停可靠性。Git/源码扫描、C++ 源码理解、MATLAB、知识库写入、长期记忆、多人权限和公网部署均不在范围内。Phase 2 的检索阈值、Top-K、候选排序、Router、提示词、答案接受条件和引用校验没有修改。

## 第一性原理与最短路径

目标用户是这台机器上的单个面试准备者，不是 API 调试者或系统管理员。最短完整路径必须是：

1. 双击 `start.cmd`；
2. 启动前检查给出可理解结果；
3. 浏览器进入 `http://127.0.0.1:8000/`；
4. 新建或恢复一个会话，提交问题；
5. 查看已校验回答、相对引用、置信提示、追问或安全错误；
6. 刷新后恢复受控历史，或删除单个/全部正文历史；
7. 双击 `stop.cmd`，进程优雅退出且不留下 PID 或监听端口。

持久化是界面恢复能力，不是 Agent 长期记忆。每轮仍只选择一个固定 namespace Tool，重新检索和建立本轮引用白名单；界面只把最近一条用户问题作为既有 `previous_question` 传入，不发送整段历史、旧回答或旧引用。

## 本地聊天界面

- FastAPI 根路径提供随 Python 包安装的 HTML、CSS 和 JavaScript，不新增 Node 运行时、前端框架、CDN 或第三方遥测；
- 首页、侧边栏、引用、追问、历史、隐私说明和移动端布局构成一个完整主流程；
- 回答和历史正文全部通过 DOM `textContent` 渲染，不使用 `innerHTML` 或 Markdown HTML 注入；
- 页面使用同源 CSP，脚本、样式和请求只能访问当前 loopback origin；
- 浏览器存储不作为权威状态，不使用 `localStorage` 或 `sessionStorage`；
- `/docs` 继续保留给开发调试，但不再是普通用户入口。

## 受控会话历史

聊天正文写入 `DATABASE_PATH` 对应 SQLite 的独立 `chat_sessions` / `chat_turns` 表。默认策略为：

- 启用历史；
- 保留 30 天；
- 最多 100 个会话；
- 每个会话最多保留最近 100 轮；
- 记录和读取时自动清理过期或超量数据；
- 提供逐会话删除和全部清空，删除正文时不破坏既有无正文审计追踪。

允许保存：当前问题、已校验回答、状态、意图、稳定错误、置信提示、建议追问和展示用相对引用。

禁止保存：检索证据正文、完整 Vault、提示词、密钥、供应方错误正文、`interview_record`、`previous_question`、LLM 请求 ID、内部 chunk/document ID、内容指纹和本机绝对引用路径。

历史写入失败时 `/ask` 返回 `history_status=failed`，界面保留回答并明确提示用户复制；不自动重试已经可能产生费用的 LLM 请求。历史关闭时返回 `disabled`，不创建聊天正文表。彻底重置运行时需要停止服务后同时删除 SQLite 与 Chroma；真实 Markdown/Vault 永远不属于清理目标。

## 启动前检查与一键启停

`scripts/start.ps1` 在创建运行时前执行以下本地检查：

- Python 版本；
- `LLM_API_KEY` 是否存在，但不读取或显示其值；
- 三个只读数据源是否存在、互斥；
- SQLite、Chroma、Embedding 缓存是否与数据源隔离；
- Markdown 是否符合白名单、UTF-8、大小和切分边界；
- 纯离线模式下模型缓存是否存在；
- 固定 `127.0.0.1:8000` 是否可绑定。

检查不加载 Embedding、不建立索引、不调用 LLM。启动脚本向子进程传入 Git 忽略的 `.run/interview-agent.json` 位置和随机停止令牌；真实 Python 服务进程原子记录自身 PID、操作系统进程映像、虚拟环境解释器和启动时间。停止脚本只有在 PID、映像和启动时间匹配后才发送令牌；服务在 HTTP 响应完成后设置 Uvicorn `should_exit`，执行完整 application shutdown。令牌入口不进入 OpenAPI，错误令牌统一返回 404。

## 实机失败归因与修复

一键流程没有只靠静态检查宣称成功。Windows 实机演示连续暴露三项问题：

1. `Start-Process` 返回的虚拟环境启动器 PID 与 Uvicorn 服务 PID 不一致，停止脚本误判服务已退出；修复为由真实 Python 服务进程写入 PID。
2. `sys.executable` 指向虚拟环境启动器，但操作系统进程映像是基础解释器，路径身份校验失败；修复为同时记录 `_base_executable` 和虚拟环境解释器，前者用于进程核验。
3. 优雅退出时 Python 已删除 PID 文件，PowerShell 再删除会把成功停止误报为失败；最终清理改为幂等。

最终实机流程通过：preflight 对当前配置的 120 个 Markdown 做只读扫描，`/health=ok`；停止后 `PidFileExists=false`、`PortListening=false`。启动前后对三个真实 Markdown 数据源计算只含相对标识和内容哈希的聚合快照，`VaultSnapshotUnchanged=true`。陈旧 PID 记录被安全忽略；服务运行时再次启动返回“已经在运行”，前后 PID 相同，没有创建第二实例。本流程没有提交或修改 Vault，没有发起问题、加载 Embedding、建立索引或调用远端 LLM。

## 剩余风险与后续决策

- 当前界面没有独立的面试复盘表单，仍可通过 `/docs` 使用 `interview_record`；历史刻意不保存该字段。
- 历史正文是本机敏感数据，没有单独应用层加密；保护依赖单用户 Windows 账户和本机磁盘权限。若设备多人共享，应关闭历史或使用系统磁盘加密。
- 历史删除不会删除不含正文的审计摘要；用户需要彻底重置时必须停止服务并同时删除 SQLite 与 Chroma。
- 启动脚本当前固定 loopback 8000 端口，不自动改端口；冲突会明确失败。
- 首次实际提问仍可能下载公开 Embedding 模型，并会按既有配置调用远端 LLM。任何新的自动化真实 LLM 验收必须重新确认模型、endpoint、次数、token、费用和允许外发范围。
- UI 的真实使用反馈尚未积累。v0.5.1 只接受可复现的可用性缺陷，不以预设功能清单自动升版本。
