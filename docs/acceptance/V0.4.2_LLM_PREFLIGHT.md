# v0.4.2：受控 DeepSeek 验收前置检查

## 状态

执行日期：2026-08-11。

v0.4.1 的匿名 holdout 与原 45-case 真实固定集均通过，没有证据要求加入混合检索、扩大候选池或独立重排模型。v0.4.2 因此只完成 Phase 2 离线收口和真实 LLM 验收夹具，不在用户确认前发起远端调用。

## 固定调用预算

`tests/test_real_llm_acceptance.py` 把真实验收固定为：

- 4 次逻辑请求，`max_retries=0`，最多 4 次 HTTP 请求尝试；
- 每次 `max_tokens=256`，总输出上限 1,024 token；
- 固定输入的保守计费预算为总计 10,000 input token；
- temperature 为 0；
- 只使用非流式 `POST /chat/completions`；
- 默认测试继续跳过，只有 `RUN_REAL_LLM_ACCEPTANCE=1` 才执行。

四个场景分别验证：公开 RAII 冒烟回答、notes 合成证据引用、项目合取事实中 Kafka 无证据时明确回答“资料无法确认”、证据内提示注入/伪造 `[S2]`/合成绝对路径不能进入回答。

## 允许外发范围

允许：

- 公开的 RAII 问题；
- 仓库内固定的合成 notes/projects 问题和证据；
- 合成引用元数据与合成 canary；
- 一条专门用于注入测试的虚构 Windows 路径。

禁止：

- 真实 notes、projects、resume Markdown；
- 真实 resume 的任何片段；
- 本机 Vault 路径、问题集、SQLite、Chroma、日志或运行时报告；
- API key 或其他凭据。

默认离线测试会检查调用数、输出上限和证据集合没有漂移。真实用例通过 `_SyntheticScopedTool` 构建证据，不加载 Vault、SQLite 或 Chroma。

## 当前官方模型与费用依据

截至 2026-08-11，[DeepSeek 官方模型与价格页](https://api-docs.deepseek.com/quick_start/pricing)列出的 OpenAI-compatible base URL 为 `https://api.deepseek.com`，当前模型为 `deepseek-v4-flash` 与 `deepseek-v4-pro`；旧 `deepseek-chat`/`deepseek-reasoner` 名称已于 2026-07-24 停用。仓库默认使用 `deepseek-v4-flash`。

`deepseek-v4-flash` 当前 cache-miss 输入价格为每百万 token 0.14 美元、输出为每百万 token 0.28 美元。按 10,000 input token 与 1,024 output token 的全部预算估算，上限约为：

`10,000 × $0.14 / 1,000,000 + 1,024 × $0.28 / 1,000,000 = $0.00168672`

即不超过约 0.002 美元；实际费用取决于供应方实际计数与当时价格，执行前应再次查看官方页面。

## 必须由用户确认

真实调用开始前，用户必须确认：

1. 模型是否使用 `deepseek-v4-flash`；
2. endpoint 是否使用 `https://api.deepseek.com`；
3. 是否允许固定 4 次、零重试请求；
4. 是否接受每次输出 256、总输出 1,024、输入计费预算 10,000 token；
5. 是否接受按当前价格估算不超过约 0.002 美元；
6. 是否只允许上述公开与合成证据外发；
7. 是否已在本机 `.env` 设置 `LLM_API_KEY`，并将 projects/resume 阈值更新为 `0.535/0.56`。

确认前不得运行真实 LLM 验收。

## 离线验证结果

- 默认套件：269 passed、2 skipped；
- 显式真实本地 Embedding：1 passed；
- 原 45-case 三源固定集：failure 0、trigger 0，指标与 v0.4.0/v0.4.1 一致；
- 报告 package version 0.4.2，Vault、隐私和 SQLite 边界全部通过；
- `compileall`、`pip check`、`git diff --check` 和高置信密钥扫描通过；
- 真实远端 LLM：未执行。

发布前完整套件还连续两次暴露 Windows 无法立即删除 `chroma.sqlite3` 的句柄问题：第一次发生在 Chroma 重启测试，第二次发生在向量索引重试测试，业务断言均已通过但 teardown 失败。根因是 Chroma 1.5.x 的已关闭 Client 仍持有 Rust server 对象。`ChromaVectorStore.close()` 现先释放 Collection，再关闭 Client、断开 wrapper 引用并在低频关闭路径显式回收 Rust wrapper。修复后完整套件通过，Chroma 与向量索引 9 项测试连续 5 轮（共 45 项）全部通过；没有在临时目录清理处增加重试来掩盖泄漏。
