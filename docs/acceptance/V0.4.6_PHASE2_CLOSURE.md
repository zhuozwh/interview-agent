# v0.4.6：Phase 2 生产装配验收收口

## 发布定位

v0.4.6 是 Phase 2 的测试与证据收口版本，不增加新的生产功能。它把此前分别通过的检索评测、独立 holdout、真实 LLM 边界和有限一轮上下文，补成从临时 Markdown 三源到 FastAPI `/ask` 返回的生产装配闭环。

本版本没有修改生产检索、阈值、Top-K、候选排序、Router、提示词或可接受答案，也没有读取或修改真实 Vault。新增内容仅为端到端验收代码、远端发送前的测试侧证据白名单、版本号和匿名验收记录。

## 第一性原理验收链

一个可结束的 Phase 2 后端至少需要证明：

1. 检索失败能区分 raw 召回、阈值、排序、事实充分性和策略错误；
2. calibration 选出的策略能原样迁移到独立 holdout，而不是用留出结果反向调参；
3. 单轮可靠后，有限上一问不能污染当前 namespace 或继承旧引用；
4. 真实模型能遵守引用、证据不足和提示注入边界；
5. 上述组件按生产装配运行时仍保持只读、隔离和审计约束。

前四项分别由 v0.4.0 至 v0.4.5 固化；v0.4.6 只补第五项。

## 固定端到端流程

测试只在临时目录创建三个互斥数据源：

- notes：公开 RAII 生命周期说明；
- projects：合成 Buffer 可读区间说明；
- resume：包含合成邮箱的合成经历，只用于本地 namespace 与脱敏检查。

流程经过生产 `Settings`、延迟运行时、本地 Embedding、Chroma、SQLite、Router、只读 Tool、RAG、回答校验、应用追踪和 FastAPI：

1. `GET /health` 不加载模型、不产生 LLM 调用；
2. RAII 问题只检索 notes 并返回本轮引用；
3. Buffer 指代追问只在兼容 namespace 时使用一条 `previous_question`，重新检索 projects；
4. 明确切换到 resume 时丢弃冲突的 projects 上一问，并在发送前脱敏合成邮箱；
5. 要求输出完整简历、全部联系方式和本机路径时返回 `policy_refused`，不调用 Tool 或 LLM；
6. 关闭运行时后比较三源指纹，确认 Markdown 零修改，并检查 SQLite 不保存问题或源正文。

## 远端边界

用户单独批准的真实冒烟参数为：

- `deepseek-v4-flash`；
- `https://api.deepseek.com`；
- 显式 `thinking=disabled`；
- 固定 2 次、零重试；
- 总输入不超过 10,000 token；
- 每次输出不超过 256 token，总输出不超过 512 token；
- 费用上限约 0.002 美元；
- 只允许公开 RAII 和临时合成 notes/projects 证据外发。

该次真实运行通过：调用数为 2/2，两次 `finish_reason=stop`，两次 reasoning token 为 0；隐私外带请求没有产生第三次调用。真实 Vault、真实 notes/projects/resume、冻结 holdout、SQLite、Chroma、本机路径和个人信息均未外发。

真实预算用尽后，测试侧进一步增加发送前白名单：每个真实 POST 必须恰好包含 system/user 两条消息，并与固定问题、intent、提示词版本、`notes|projects` namespace、相对文件名和完整合成正文逐项一致；出现额外协议字段、合成 resume、合成邮箱、脱敏邮箱、`file://`、Windows 盘符或常见用户目录时，在构造远端请求前失败。该增强同时使用确定性探针和生产装配实际生成的消息离线验证，没有重复远端调用或费用。

## 指标与阶段结论

v0.4.6 没有重新选择阈值或使用 holdout 调参，因此沿用 v0.4.5 的正式结果：

- legacy 45-case：Router 100%、Hit@1 85.71%、Hit@5 100%、MRR 0.916667；
- 硬负例拒绝、跨 namespace 拒绝、Agent 正负边界和引用完整性均为 100%；
- 用户独立冻结集的 calibration/holdout 两个 split 全指标 100%，19 个 probe 全部通过；
- 真实 Vault 未修改，运行时数据继续与三个只读源隔离。

Phase 2 核心后端目标至此完成。当前固定证据仍不支持引入混合检索、扩大候选池或第三方重排组件。

## 剩余边界与下一决策

- 当前可用入口是本地 FastAPI `/docs` 和 `/ask`，没有面向普通用户的独立 Web 前端；
- 多轮只支持一条显式上一问题，不持久化旧回答、旧引用或长期记忆；
- 事实锚点门控不是开放域语义蕴含模型；
- 输出侧完整语义 DLP 仍按单机单用户范围暂缓；
- 真实个人资料发送给 DeepSeek 不在本版本授权范围内，首次真实 Vault 在线使用仍需单独确认；
- Git 源码、MATLAB 理解和知识库写入属于 Phase 3/4，不在本阶段。

后续只有两类合理动作：修复真实使用中新出现且能固定复现的 Phase 2 缺陷，或由用户明确决定进入 Phase 3。不得为了继续迭代而制造新的检索复杂度。
