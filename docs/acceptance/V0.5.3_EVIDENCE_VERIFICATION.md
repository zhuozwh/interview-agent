# v0.5.3：本地引用证据核验验收

## 第一性原理与范围

执行日期：2026-08-31。

使用者仍是本机单个面试准备者。用户需要解决的不是“看到一个引用标签”，而是判断回答是否真的受到自己的资料支持。最短完整路径是：打开已有或新保存的会话、阅读回答、点击结构化引用、在右侧核对当前本地 Markdown 原文、关闭面板并决定是否采用回答。该路径不要求用户理解 FastAPI、SQLite、绝对路径或检索实现。

需要持久化的状态没有扩大：SQLite 继续只保存受控会话正文和展示引用元数据。证据正文、完整文件、文件快照、绝对路径、检索内部 ID 和浏览器状态都不新增持久化。删除会话或清空历史后，对应引用身份随正文历史一起消失；历史关闭或本轮保存失败时，引用仍可展示但不能通过不受控路径重新打开。

失败边界是：浏览器不能指定 namespace、文件路径或行号；历史记录必须同时匹配 session、trace 和 citation；服务端只把三个固定 namespace 映射到配置的数据源根；规范化后的文件仍须位于源根和允许目录内，是存在的 UTF-8 Markdown，并满足文件大小与行号上限。任一条件失败只返回固定 4xx/5xx 错误，不回显本机路径或底层异常。面板展示当前文件而不是回答时快照，因此必须明确提示文件编辑后可能不同；检索分数只表示相关性排序，不得包装成正确率。

可验证验收标准：有效已保存引用能展开准确行段；恶意正文只作为文本；客户端路径伪造无入口；目录穿越、未知域、失效来源、超大文件、非法 UTF-8 和越界行号失败关闭；证据正文不进入 SQLite 或浏览器存储；历史关闭不建立数据库；删除/保存失败不保留旁路；Phase 2 检索与回答边界零变化；默认测试不联网、不读取真实 Vault、不调用真实 LLM。

## 实现

- 新增独立的本地证据读取器，对固定 source root、允许目录、规范化真实路径、Markdown 后缀、UTF-8、文件字节、行跨度、展示行数和字符数执行双层限制。
- 新增应用服务，先从会话历史按三个规范身份定位唯一引用，再把 `notes`、`projects`、`resume` 映射到配置的三个固定只读目录。HTTP `GET /api/evidence/{session_id}/{trace_id}/{citation_id}` 不接受 query/body 路径参数，所有响应包含 `Cache-Control: no-store` 和 `Pragma: no-cache`。
- 引用标签在历史确实保存后才成为按钮；点击后右侧面板显示资料域、相对路径、标题路径、原引用行号、当前展示行号、相关性分数和纯文本原文。关闭按钮、遮罩和 Escape 均可退出。
- 面板不用 `innerHTML`、外部脚本、浏览器 `localStorage` 或 `sessionStorage`。证据中的 `<script>`、HTML 和 Markdown 只进入 `textContent`。
- `application` 公开包改为按符号惰性导入，修复独立进程先导入 storage 时的循环依赖；公开名称保持不变。
- Tool 审计查询在时间戳并列时按 SQLite 实际写入序号读取，修复 Windows 低分辨率时钟下随机 UUID 打乱审计先后的问题。该修复不改变 Tool 检索输入、输出或路由。

本版本没有增加会话 schema，没有修改 Phase 2 阈值、Top-K、候选排序、Router、RAG、提示词、回答接受条件或引用完整性校验，也没有实现联网搜索、源码/MATLAB 理解或知识库写入。

## 对抗测试、失败归因与修复

| 场景 | 失败边界或预期 | 结果 |
|---|---|---:|
| `../`、绝对路径、驱动器、反斜杠、`.` 分段、非 Markdown | 不能成为任意文件接口 | 通过 |
| 符号链接解析到白名单外 | 真实目标必须再次通过源根和允许目录检查 | 代码边界通过；本机无创建符号链接权限，测试显式 skip |
| 缺失文件、引用行已消失、超大文件、非法 UTF-8 | 固定 410，不泄漏路径 | 通过 |
| 伪造 session、trace、citation 或未知 namespace | 422/404/410，不能猜测或回退 | 通过 |
| 历史关闭但目标文件存在 | 404，且不建立 SQLite | 通过 |
| 原文包含 `<script>` | JSON 保留文本，界面只用 `textContent` | 通过 |
| 证据正文唯一标记 | API 可读取，但 SQLite 字节中不存在 | 通过 |
| 字符预算截在中间行 | 当前展示末行必须按实际内容计算 | 首轮发现并修复 |
| 独立进程先导入 storage | 不依赖全量测试的偶然预热顺序 | 首轮发现循环导入并修复 |
| 三次 Tool 同 trace、同系统时间戳 | 审计保持真实写入顺序 | 10 次压力测试曾复现 1 次；修复后 10/10 通过 |

初次全量回归得到 **357 passed、5 skipped、1 failed**。唯一失败的 Tool namespace、返回内容和简历脱敏断言均已通过，失败只发生在审计记录顺序；压力测试确认 Windows 连续调用可共享同一时间戳，而旧查询用随机 UUID 作为并列键。修复为按插入序号并列排序后，定向套件为 **36 passed、1 skipped**，同一测试连续 10 次 **0 failure**。

最终默认离线全回归为 **361 passed、5 skipped**。其中四个既有 skip 仍是必须显式启用的真实本地 Embedding 或远端 LLM 入口；新增一个 skip 是当前 Windows 账户缺少创建符号链接权限。Node 两个脚本语法检查、Python `compileall` 和 `git diff --check` 均通过。

在 8011 端口以 `SESSION_HISTORY_ENABLED=false` 临时冷启动当前包，只访问首页、`/health`、主脚本和一个不存在的证据身份：页面 200 且含证据面板，健康状态为 `ok`，脚本 200，证据身份 404；随后端口停止监听。过程没有请求 `/ask`、建立历史数据库、加载或下载 Embedding、创建索引、读取真实 Markdown 正文或调用远端 LLM。

## 指标与剩余风险

- Phase 2 固定检索指标未重跑或重算，因为生产检索、排序和回答链没有变化；v0.4.5/v0.4.6 的匿名指标继续有效。本版本新增通过项只证明产品核验、安全边界和审计稳定性。
- 证据面板能让用户发现引用不相关，但不能自动证明回答每句话被证据语义蕴含。v0.5.2 已记录的 notes `0.5850` 假阳性仍存在，不能在本里程碑通过调整阈值、扩大答案或删除样本制造绿灯。
- 当前文件不是回答时快照。这样避免把真实 Vault 正文复制进 SQLite，但文件后来修改时只能提示漂移，不能还原回答当时证据。若未来确需可追溯快照，需要单独设计加密、生命周期、删除和迁移策略，不能静默扩充历史。
- 无历史模式和历史保存失败的即时回答引用不能展开，因为服务端没有可验证的持久身份。直接允许浏览器回传路径会破坏失败边界，因此保持不可展开并给出说明。
- 符号链接攻击已由解析后路径双重检查覆盖，但本机测试账户无法实际创建链接；应在具备链接权限的 CI/开发环境中消除该 skip。
- 联网搜索属于单独的外部信息能力，尚未实现。开始前需要确定来源可信度、外部/本地证据标签、缓存与隐私、网络失败、引用去重和用户是否允许把问题外发；不得与本地证据面板混为同一可信域。

## 发布结论

v0.5.3 达到“用户可从回答进入当前本地原文核验，同时不扩大持久化和文件读取权限”的目标。默认离线与冷启动验收通过，Phase 2 生产回答边界未改动，没有新的远端调用授权或调用。发布前仍需按里程碑规则检查工作树只含本阶段预期文件，再提交、创建详细 annotated tag 并推送。
