# v0.4.4：有限一轮上下文与引用一致性

## 结论

执行日期：2026-08-11。

v0.4.4 完成 `previous_question` 的 Phase 2 收口：当前轮明确 namespace 永远优先；只有当前轮存在显式指代且两轮数据域兼容时，才合并一条上一轮用户问题。系统仍不保存上一轮正文，不继承旧回答或旧引用，每轮重新选择唯一只读 Tool、重新检索，并只接受当前证据包中的引用。

本轮没有改动检索阈值、Top-K、答案接受条件、提示词或 LLM 客户端，也没有调用任何远端 LLM。

## 第一性原理不变量

1. 当前请求是唯一授权边界：旧 namespace 不能覆盖当前轮明确意图；
2. 上一问只用于消解当前轮显式指代，不是长期记忆或第二数据源；
3. 每轮最多选择一个固定 namespace Tool，不因上下文扩大检索链；
4. 明显隐私外带意图必须在 Embedding、Vault 读取和 LLM 前停止；
5. 引用白名单只由本轮 Tool 响应构建，旧 `[S数字]` 永远无效。

## 真实失败与归因

修复前实现先把“上一轮问题 + 当前追问”拼接，再交给 Router。Router 对 resume 明确标记的优先级高于 projects，因此“上一轮问简历、当前明确问这个项目”会被旧 resume 标记带偏，属于 **上下文状态优先级错误 / 路由漂移**，不是召回失败、阈值误杀、排序错误或 LLM 错误。

新增失败测试先稳定复现两种跨域切换；随后只在引用消解层加入显式 namespace 冲突判定。当前轮与上一轮都明确声明且互相冲突时，返回当前问题并标记未使用上下文；同域或当前轮只有指代时仍保留原有一轮继承能力。

## 冻结匿名对抗集

仓库新增 8-case `phase2_v044` 固定矩阵：

- notes、projects、resume 各一个兼容指代正例；
- resume -> projects 与 projects -> resume 两个当前轮覆盖样本；
- “应该”不得因包含单字“该”误触发上下文；
- 无指代的新知识问题不得继承旧简历问题；
- 分两轮组成的完整简历、全部联系方式和本机绝对路径外带必须在检索前拒绝。

Agent 层另行验证三域追问都只调用一次本轮唯一 Tool、冲突上一问不会进入 Tool 查询或 LLM 问题、跨轮隐私请求为零 Tool/零 LLM，以及伪造旧 `[S2]` 在当前证据只有 `[S1]` 时整条回答失败。

## 剩余边界与人工节点

- Phase 2 尚缺由用户人工独立冻结、未参与既有规则设计的真实 Vault holdout 问题；不能由旧 45-case 自动改写后冒充独立样本；
- 一轮显式上下文不等于长期会话记忆，不支持自动摘要、多 Tool 规划或旧回答引用；
- 完整输出侧语义 DLP 按当前单机单用户范围继续暂缓，保留既有确定性脱敏和明显外带意图停止；
- 混合检索或独立重排仍无固定评测必要性证据，不引入；
- Phase 3 的源码/MATLAB 理解、知识库写入和复杂前端不在本版本范围。
