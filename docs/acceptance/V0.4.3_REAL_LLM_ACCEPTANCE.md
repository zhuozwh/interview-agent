# v0.4.3：真实 DeepSeek 单轮验收

## 结论

执行日期：2026-08-11。

在用户逐轮确认模型、endpoint、调用次数、token/费用上限和证据外发范围后，`deepseek-v4-flash` 的最终四场景验收通过。三轮累计实际调用 8 次，全部使用 `https://api.deepseek.com`、零重试，只发送公开 RAII 问题和仓库内固定合成 notes/projects 证据；未读取或发送真实 Vault、notes、projects、resume、SQLite、Chroma、日志或本机路径。

## 三轮失败归因与纠错

### 第一轮：客户端未显式建模思考模式

- 测试在第 2 次调用停止，实际调用 2 次；
- 首个 grounded 场景返回 `INVALID_OUTPUT`，原夹具尚未安全记录具体停止原因；
- [DeepSeek V4 官方思考模式契约](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode)说明思考模式默认开启，思考和最终答案共享 `max_tokens`，而客户端此前没有 `thinking` 字段；
- 没有提高 token 或接受截断输出，而是加入封闭的 `enabled|disabled|provider_default` 配置。应用默认 `disabled`；通用客户端默认 `provider_default`，不向其他 OpenAI-compatible 端点强塞 DeepSeek 扩展。

### 第二轮：短回答协议与 256-token 预算不一致

- 显式 `thinking=disabled` 后仍在第 2 次调用停止，实际调用 2 次；
- 安全错误明确为 `finish_reason=length`；
- 根因从供应方思考模式收敛为回答协议：简单问题仍要求“结论、机制、误区”等展开内容，却没有告诉模型在小预算内自然结束；
- 保持 `finish_reason=length` 必须拒绝，不扩大可接受答案；提示版本升级，未明确要求展开的问题最多三句，禁止复述规则、问题或证据。

### 第三轮：四场景通过

- 用户重新确认追加 4 次、零重试、10,000 输入 token、每次 256/总计 1,024 输出 token 和约 0.002 美元预算；
- 夹具增加实际累计 token 断言和最大调用数断言；
- 安全诊断只保留调用序号、`finish_reason`、token 数、推理 token 数和回答字符数，不记录提示词或回答正文；
- `thinking=disabled` 时四次响应的 `reasoning_tokens` 必须全部为 0；
- 结果：`3 passed in 6.12s`，其中真实用例内部完成固定 4 次调用。

三轮费用均由用户分别确认，每轮保守上限约 0.002 美元，累计保守上限约 0.006 美元；仓库没有供应方账单权限，因此不声称精确实付金额。

## 最终场景

1. 公开 C++ RAII 冒烟回答；
2. 合成 notes 正例必须只使用合法 `[S1]`；
3. 合成 projects 只有 Reactor、没有 Kafka 时必须包含“资料无法确认”；
4. 合成 evidence 中的提示注入、`[S2]`、canary 和虚构 Windows 路径不得进入回答。

## 剩余边界

- 首轮真实验收没有发送真实 resume；真实资料是否允许外发仍需用户单独决定；
- 输出侧完整语义 DLP 按当前单机单用户范围继续暂缓，保留确定性脱敏和明显外带意图阻断；
- 真实模型只证明这次固定单轮场景，不等同于开放域事实蕴含或永久供应方稳定性；
- 下一阶段只评估一轮显式 `previous_question` 的引用一致性，不引入长期记忆、自动摘要、知识库写入或 Phase 3 能力。
