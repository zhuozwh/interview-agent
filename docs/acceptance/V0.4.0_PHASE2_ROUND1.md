## 状态与边界

执行日期：2026-08-10。

本轮从 `main`、本地 `origin/main` 和 annotated `v0.3.2` 共同指向的 peeled commit `656e9826ef328d994489469b527bbe7831049e1c` 开始。v0.3.2 未修改；当前变更未 commit、未打 tag、未 push。

本轮只使用本地 FastEmbed、隔离 SQLite/Chroma、确定性 LLM 替身和匿名报告：

## 第一性原理归因

一次检索与回答被拆成五个可独立验证的判定点：

1. 检索前策略是否应因明显数据外带或 namespace 不匹配而停止；
2. 正确片段是否进入未阈值过滤的原始 Top-K；
3. 正确片段是否被 namespace 阈值误杀；
4. 正确片段是否被相邻、历史或主题相似片段压制；
5. 候选是否足以证明“存在、使用、做过”，以及 Agent 是否正确拒答并只引用本轮证据。

报告 schema v2 为每个 probe 记录 `raw_hit_rank`、`raw_hit_score`、生产阈值、Tool `decision_code`、最终排名和以下稳定诊断：

- `recall_miss`；
- `threshold_false_rejection`；
- `ranking_error`；
- `fact_sufficiency_false_rejection`；
- `cross_namespace_policy_error`；
- `fact_existence_error`；
- `retrieval_false_acceptance`。

这使召回、门控、排序、事实和策略失败不再被合并为单个“答错”。

## 基线失败与对应修复

| 基线证据 | 归因 | 本轮最小修复 |
|---|---|---|
| P03、P04 正确项目片段低于统一 `0.58` | 阈值误杀；P04 另有排名压力 | projects 阈值改为 `0.535`，只在原始 Top-K 内做轻量一致性排序 |
| R03、R04、R08 正确简历片段被阈值或历史片段压制 | 阈值误杀与排序错误 | resume 阈值改为 `0.56`；当前/历史限定参与小幅候选内排序 |
| HN11 以 Buffer“扩容”替代 Kubernetes/HPA 事实 | 事实存在性错误 | projects/resume 候选必须直接出现至少一个具体技术或实体锚点 |
| R01 在 notes/projects 被相似主题错误接受 | 跨 namespace 策略错误 | Router 与三个 Tool 共用确定性 namespace 判定，并在 Embedding 前停止不匹配查询 |
| RHN04 请求原文、全部联系方式和绝对路径 | 检索前策略错误 | 高确定性的批量、原样、绕过或本机路径外带在 Tool 和 LLM 前停止 |
| RHN05 以其他实习片段证明指定公司经历 | 事实存在性错误 | 提取引号实体、技术标识、常见组织名称和属性对，缺少直接证据时返回 `no_results` |

没有修改问题、删除失败 case、添加部分相关来源或扩大“可接受答案”。

## namespace 代价矩阵

固定权重为：关键正例误拒绝 2、普通正例误拒绝 1、硬负例误接受 4、跨 namespace 误接受 5。

| namespace | 当前阈值 | 策略感知 TP/FN/TN/FP | 策略感知代价 | 纯阈值当前 TP/FN/TN/FP | 纯阈值代价 | 最佳纯阈值仍有的错误 |
|---|---:|---:|---:|---:|---:|---|
| notes | 0.58 | 12 / 0 / 11 / 0 | 0 | 12 / 0 / 10 / 1 | 5 | `0.632754` 可分开当前集，但无需为单个跨域碰撞提高生产阈值 |
| projects | 0.535 | 8 / 0 / 8 / 0 | 0 | 8 / 0 / 4 / 4 | 19 | `0.625749` 仍误拒绝 2 个正例，代价 4 |
| resume | 0.56 | 8 / 0 / 5 / 0 | 0 | 8 / 0 / 2 / 3 | 12 | `0.606589` 仍误拒绝 3 个正例，代价 6 |

结论：projects/resume 不存在能同时满足当前正负例的单一阈值。独立阈值必须与 namespace 和事实充分性策略共同使用；单纯调参无法制造真实绿灯。

## 匿名合成集与有限多轮

仓库内确定性验收从原有基础场景扩展到以下匿名对抗类型：

- 项目“扩容”主题对 Kubernetes/HPA 事实的碰撞；
- 指定公司经历不存在；
- 原样简历和全部联系方式外带；
- 显式跨 namespace 探测；
- 当前版与历史版排序；
- 一轮 `previous_question` 指代消解；
- “应该”不被单字“该”误判为引用；
- 当前轮只有 `[S1]` 时拒绝沿用上一轮 `[S2]`。

问题集 schema v2 可选保存一条上一问题。只有当前问题出现明确指代时才合并；上一轮回答、证据和引用不进入请求。每一轮仍重新选择唯一 Tool、重新检索并重新建立引用白名单，SQLite 不保存问题正文。

## 反思检查与剩余风险

- 事实锚点只能证明具体词或实体在候选中直接出现，不能自动证明整句话被证据语义蕴含；提示词要求逐项把缺失对象回答为“资料无法确认”，真实模型行为仍待单独验收。
- 候选排序是原始 Top-K 内最多 `0.03` 词面和 `0.04` 时间一致性的小幅修正，不扩大召回；仍有 4 个非 Top-1 正例被如实记录。
- 明显外带策略只覆盖高确定性的批量、原样、规则绕过、联系方式和本机路径组合，不是完整输出侧语义 DLP；这与已确认的单机单用户接受风险一致。
- 有限多轮由调用方显式传入上一问题，不是服务端记忆；两轮以上、自动摘要、会话正文持久化和复杂指代不在本轮范围。
- 真实 DeepSeek 验收尚未执行。到该节点前必须另行确认模型与 endpoint、调用次数、token 上限、预计费用和允许外发证据范围；首轮不得发送真实 resume 片段。
