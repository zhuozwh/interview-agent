# v0.3.2 安全收口与 Phase 2 前置边界

## 发布定位

v0.3.2 是 v0.3.x 的最终安全收口版本，用于补齐真实 Vault 基线之后发现的运行时只读正确性缺口，并把安全审查、威胁模型、接受风险和 Phase 2 边界固化到仓库。它不包含混合检索、重排序、阈值校准、复杂 Router、多轮规划或其他 Phase 2 功能。

`v0.3.1` 标签保持不可变，继续代表真实 notes/projects/resume 三源匿名效果基线；v0.3.2 在其基础上增加安全工程和发布证据。

## 变更范围

- 将 OpenAI 官方 `security-best-practices` 和 `security-threat-model` 作为仓库级 Skill 纳入 `.agents/skills/`。
- 新增安全最佳实践审查报告和仓库证据驱动的威胁模型。
- 正常应用在创建 SQLite、Chroma 或 FastEmbed 模型缓存前，拒绝运行时路径位于任一只读数据源内。
- 对 Chroma 和模型缓存这类目录型运行时根，同时拒绝其反向包含数据源，降低后续重建或人工清理误伤原文的风险。
- 新增 5 个对抗测试，覆盖三种“写入数据源”配置和两种“运行时目录包含数据源”配置，并确认拒绝发生在目标创建之前。
- 记录单机单用户边界下暂缓 LLM 输出语义 DLP 的用户决策和重新开启条件。
- 项目版本从 `0.3.1` 更新为 `0.3.2`。

## 接受风险与停止条件

### 当前接受

- LLM 输出没有覆盖任意自由文本隐私的完整语义 DLP。
- FastAPI 没有用户认证，安全边界依赖默认 `127.0.0.1`。
- notes/projects 资料可能包含正则脱敏未覆盖的自由文本隐私；真实 LLM 调用仍需最小化证据并由用户明确批准。
- 本地 SQLite/Chroma/模型缓存依赖 Windows 账户和磁盘权限保护。
- 依赖使用主版本有界的版本区间，没有仓库 lockfile。

### 必须重新开启安全设计的条件

- 服务监听非 loopback、经反向代理共享或对公网开放。
- 增加第二个用户、租户或权限角色。
- 索引自动抓取、第三方或其他不可信来源。
- 新增自动写回、文件修改、代码执行或外部 Tool。
- 更换 LLM/Embedding 供应方，或扩大远端发送的数据范围。
- 处理护照、银行卡、医疗、账户凭据等新数据类别。

任一条件成立时，不能沿用本版本的接受风险结论。

## 版本边界

- `v0.3.0`：Phase 1 功能闭环。
- `v0.3.1`：真实 Vault 三源只读基线和隐私正确性修复。
- `v0.3.2`：Phase 1 运行时写入边界、安全审查和威胁模型收口。
- `v0.4.0`：Phase 2 开始；首次允许针对基线证据修改检索、阈值、排序和拒答策略。

除非 v0.3.2 发布核验再次发现新的 Phase 1 Critical/High 或只读正确性缺陷，否则不再增加 v0.3.x 功能或补丁。
